# 跨網段身分同步管線 — 精進報告與 AI 導入評估

| 項目 | 內容 |
|------|------|
| 文件類型 | 系統精進提案 / 技術評估 |
| 適用系統 | 內中外三網身分與憑證同步管線 |
| 技術棧 | 排程任務服務、PostgreSQL、Podman(RHEL)、AD Password Filter |
| 版本 | v1.0(初稿) |

---

## 摘要

本系統是一套**跨實體隔離網路的身分與憑證同步管線**:於內、中、外三個隔離網段之間,透過排程任務服務搭配 PostgreSQL 進行資料交換;帳號密碼變更由 AD Password Filter 於來源端攔截後寫入內網資料庫,隨身分資料一同交換至外網;外網端再與外網 AD 比對差異,執行帳號異動。由於內、外分屬不同 AD 網域,本質上是**跨網域身分佈建(provisioning),而非目錄複寫(replication)**。

過去一段時間的維運中,已定位並修復數項穩定性與資源問題,系統可用性顯著改善。本報告盤點現況、彙整已完成的改善,提出下一階段的架構簡化與韌性強化方向,並就「是否導入 AI」提出務實評估——**核心結論是:同步與異動決策必須維持確定性,AI 的著力點在管線周邊的觀測、異常偵測與根因分析,且因機敏資料不得上雲,任何 AI 皆須於地端離線運行。**

---

## 一、現況架構

### 1.1 系統定位

不是「一組排程任務」,而是一套支撐跨隔離網段帳號生命週期的**身分同步基礎設施**。它同時承載兩類資料:

- **身分物件**:使用者、群組、OU 等目錄資料
- **憑證資料**:由 AD Password Filter 攔截的密碼變更

### 1.2 資料流

```
內網 AD ──(Password Filter 攔截密碼 + 目錄資料)──▶ 內網 DB
   │
   ▼  排程任務服務 / DB-to-DB 交換
中段暫存
   │
   ▼  跨網段交換
外網 DB ──▶ 與外網 AD 比對差異 ──▶ 執行帳號異動
```

### 1.3 關鍵約束

| 約束 | 說明 |
|------|------|
| 實體隔離 | 內中、中外採定時切換,無穩定的常時雙向連線 |
| 跨網域 | 內、外分屬不同 AD 網域,SID/DN 皆不同,需以佈建方式處理 |
| 憑證敏感度 | 密碼資料流經多個 DB 與網段,為全管線風險最高的一段 |
| 機敏不上雲 | 所有處理須留在地端,任何外部服務(含 AI)皆不可行 |

## 二、問題盤點

### 2.1 穩定性

- **排程任務間歇凍結**:單次凍結逾一小時。追查後定位為資料匯入(`\COPY`)過程中 TCP 連線靜默中斷卻未釋放,疑似受網段切換週期與作業系統核心更新交互觸發。
- **切換邊界脆弱性**:任一操作若跨越網段切換時點,即可能懸置——這是凍結問題的結構性根因。

### 2.2 資源與可觀測性

- **日誌異常暴增**:源於失敗的 CSV 匯出產生異常 SQL,以及資料庫 collation 版本不一致。
- **容器日誌路由**:Podman 的 journald 日誌驅動將容器輸出導入系統訊息檔,造成日誌混雜與膨脹。

### 2.3 架構性風險

- **單向交換無回饋**:外網端處理成功與否,內網端無從得知,缺乏閉環確認。
- **截斷資料誤判**:若交換檔案不完整,差異比對可能誤判為「大量帳號消失」,進而觸發大規模帳號停用。
- **憑證資料落地風險**:密碼於多段暫存,加密、保留期限與傳輸保護需明確規範。

---

## 三、已完成的改善

| 面向 | 措施 | 效果 |
|------|------|------|
| 連線韌性 | 連線字串加入 TCP keepalive 參數;遠端指令以 `timeout` 收尾 | 消除靜默 hang 導致的長時間凍結 |
| 失敗處理 | 執行前先做連線預檢,失敗時乾淨退出 | 避免半途失敗殘留 |
| 資料庫 | staging table 關閉 autovacuum;修復 collation 版本不一致 | 降低干擾與日誌噪音 |
| 日誌 | 容器日誌驅動改為 k8s-file | 日誌歸位、易於分析 |

此階段證明改善是持續且有成效的,並為下一階段的架構調整奠定基礎。

## 四、精進方向

### 4.1 架構簡化:評估收斂為「內 → 單向閘 → 外」

現有單向閘為**真單向、隨時可傳**,足以承接中段暫存原本的解耦角色。評估拔除中介、簡化為兩段式:

```
內網匯出 ─▶ 推送單向閘 ─▶ 外網收檔驗證 ─▶ 匯入比對 ─▶ 異動外網 AD
```

**注意事項**:單向閘無回饋路徑,內網無法得知外網結果。因此簡化的前提是「所有安全與確認機制移至外網端自我把關」。需以單一案場試點驗證後再推廣。

### 4.2 韌性強化

- **小批化**:將大型匯入與批次異動切成能在「最短切換窗口」內從容完成的小批,避免跨越切換點。
- **高水位續跑**:以變更序號 / DirSync cookie 記錄進度,中斷後由水位接續,不重頭再來。
- **增量比對**:以 AD 的 DirSync 機制取代全量比對,降低成本並確保刪除(tombstone)不漏。

### 4.3 安全把關(單向無回饋,外網端為最後防線)

- **完成驗證閘**:交換檔附 checksum / manifest,外網端**先驗證再匯入**,擋掉截斷檔。
- **刪除門檻閘**:單次異動若停用/刪除超過設定門檻(筆數或百分比),即中止並告警、待人工確認。此為防止大規模誤刪的唯一防線,不可省略。
- **跨網域錨點**:以 objectGUID 作為跨網域對應錨點(而非 DN 或 SID),正確處理 OU 重掛、重名衝突與屬性轉換。
- **冪等套用**:套用邏輯以「調整為目標狀態」設計,重複執行安全。
- **自我修復狀態**:傳輸完整狀態快照(或帶序號的基準+增量),使單次遺失可由下一輪自動收斂,避免長期漂移。

### 4.4 可觀測性

- **外網端監控**:因內網端無回饋,告警須由外網端發出(如「逾時未收到有效檔」「差異超門檻已中止」)。
- **異動稽核軌跡**:每筆 AD 異動記錄前後值,以利回滾與稽核。

### 4.5 憑證安全(建議獨立列管)

- 密碼落地加密、最短保留期限、傳輸過程保護。
- 明確界定憑證資料在各網段的存續與清除規則,並保留稽核紀錄。

## 五、AI 導入評估

### 5.1 基本原則(負責任導入)

> **AI 不進入同步、比對、AD 異動決策的關鍵路徑。**
> 此路徑必須為確定性的規則邏輯——不應由機率模型決定是否停用帳號。

明確劃出此紅線,是本評估的立場,也讓導入更具說服力。

### 5.2 有著力點的方向(管線周邊,非核心)

| 方向 | 說明 | 與現況痛點的連結 |
|------|------|------------------|
| **異常偵測** | 以機器學習監看交換量測與日誌,偵測差異量暴增、執行時間異常、日誌暴增前兆、連線懸置徵兆 | 強化「刪除門檻閘」,使判斷由學習得出而非寫死 |
| **地端離線日誌分析 / 根因輔助** | 以**地端離線 LLM** 跨層關聯排程任務、資料庫與容器日誌,摘要故障、推測根因 | 直接呼應既有故障排除需求,且符合「機敏不上雲」 |
| **預測性維運** | 由連線延遲爬升等模式,預測凍結/失敗於發生之前 | 從被動修復轉為主動預防 |
| **身分資料品質分析** | 找出異常帳號、孤兒 OU、內外漂移、異常權限模式 | 為未來帳號治理鋪路 |

### 5.3 亮點試點建議

**地端離線 AI 日誌與異常分析** 是本提案最具收斂性的試點:

- 解決現有的故障排查與異常偵測痛點
- 完全符合機敏資料不得上雲的原則(模型於地端運行)
- 同時驗證「離線 AI」在隔離環境中的可行性,為後續應用累積經驗

### 5.4 不建議的方向(展現判斷)

- 以 AI 執行實際差異比對或決定 AD 異動(須維持確定性)
- 以生成式 AI「代寫同步邏輯」(現有邏輯已成熟)
- 為導入而導入的聊天機器人

### 5.5 定調

> AI 在此的角色是「管線的眼睛」——地端的觀測、異常偵測與根因分析;
> 而非「管線的手」——同步與套用維持確定性。
> 且因機敏不上雲,任何 AI 皆須於地端運行,這正好讓離線 AI 的探索有了真實落地場景。

| 面向 | 效益 |
|------|------|

| 安全合規 | 稽核軌跡完整;門檻閘防止大規模誤刪;憑證管理明確 |

## 七、風險、資源與時程(建議分階段)

| 階段 | 內容 | 驗證方式 |
|------|------|----------|
| 第一階段 | 韌性強化(小批化、水位續跑、完成驗證閘、門檻閘) | 單一案場試點,監測凍結與誤判是否消除 |
| 第二階段 | 架構簡化評估(收斂為單向閘兩段式) | 試點比對簡化前後穩定性,附回滾方案 |
| 第三階段 | 地端離線 AI 日誌/異常分析試點 | 以歷史故障案例驗證根因命中率 |
| 第四階段 | 憑證安全列管與稽核強化 | 資安 / 稽核檢視 |

**風險控管**:每階段先於單一案場試點、保留回滾方案,確認穩定後再推廣至多案場。

---

## 結語

本系統已從多次維運事件中累積出清楚的痛點圖像與修復經驗。下一階段的重點,是把「被切在半路就懸置」這類結構性弱點,透過小批化、水位續跑與外網端自我把關,轉為可自我修復、跨案場自適應的穩健管線;並以**地端離線 AI** 作為觀測與異常偵測的輔助層——在不觸碰確定性關鍵路徑的前提下,既解決現有痛點,也為隔離環境下的 AI 應用開出一條務實可行的路。
